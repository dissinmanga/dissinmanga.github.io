對好東西，向來我是站一個很隨緣的角度；但git是例外，如果有在寫markdown的同好，我感覺是很值得花一點時間摸摸看，只要在你的白老鼠目錄下一個`git init`，它只會在下面建一個`.git`的目錄，若試著不喜歡，把那個目錄砍了就恢復原狀了。

他的概念簡單講就是把`部落格_congo_theme_added版`、`部落格_add_post版`、`部落格_clear_slugs版`…等一連串分開存的檔案整理成下圖左下角那個依照時序排列的線狀圖，一個版就對應到一個commit。

![](/blogpics/261126_workspace.webp)

我想微軟的工程師應該會比我還要懂怎麼把git做到你阿嬷也學得會，所以我用vscode舉例，如果今天我想要把這篇文章定成一版時：

+ 在圖片左上角處把想要定版的檔案按按加號（stage）
+ 在message欄填入你喜歡的版本名字
+ 按commit

這樣，就定好一版了，這時你從左下角選一個commit裡的某個檔案，vscode會把那個檔案在過去與現在的差異列給你看。

如果哪天真的不想再用vscode的話，上面這些功能其實對應到這些指令：

+ `git add [file]`
+ `git commit -m [message]`

其他更複雜的功能，等需要再慢慢查就行了。

若要說`git`跟分開存檔案的差異，那就是，假設哪天有人問我這個網站的飄雪特效怎麼做的（不會有這種人），我就可以在github[^4]上翻到對應的commit，然後把差分連結丟給他。一個當時的我用超低成本留一句記錄來造福未來的我的概念。

我很少會講工具，不過因為一些經歷，我是篤信「工欲善其事，必先利其器」的，~~等術式刻在身體裡後再把輔助輪拆掉就好~~。而大概因為我離不開一個工具的點都很奇怪，所以也是能寫成一篇文。

以這個小盆栽來說，我是以obsidian為[主力]({{<relref "260916_move_to_hugo">}})，obsidian畫起表格的體驗超級舒服[^1]，不過當我想動markdown以外的檔案時就必須改用vscode或vim[^2]。寫到這裡時我突然發現這完全是小時候的我會困惑的行為（為什麼除了IE外還要有火狐呢？），而我居然已經對電腦裡有vscode、vim和zed等三套編輯器感到司空見慣。

寫著寫著我竟感到一陣鼻酸，在大AI時代寫這些事，感覺就像是在聊哪種毛筆的吸墨力比較強、刷毛比較不會分叉一樣。

不過，如果在這年頭還想體驗一點寫寫程式的樂趣，vscode和zed的自動補全與自動排版，甚至是method定義預覽功能等，用起來會舒服很多。而我居然只是因為zed內建了vim mode[^3]跟我習慣的syntax highlighting theme而成為它的忠實用戶。

太膚淺了吧！

只有在失去時才會珍惜，雖然早在vscode橫空出世時就終結了vim與emacs之爭，但在這年頭，在逐漸沒有人會感受到editors的方便之處時，我才開始懷念起那些宗教戰爭的活力。不過，如果把成品交付他人的需求，那個相互討論打磨一件事物的需求不消失的話，我想git的生命力大概能持續很長的一段時間。

[^1]: 作為一個時常認為GUI生雞蛋沒有放雞屎一堆的人，obsidian是少數我會用的editor，但對不熟悉markdown語法的人來說，實用性會打好幾折的樣子，這之間的平衡感真的不好抓。

[^2]: 我曾想刻意練習，只是vim是個滿吃plugins的editor，我曾經花了億點心力研究，但在引入其他語言的LSP這步打退堂鼓，這一路上的閉門造車曾讓我多次想看看別人怎麼使用vim的，但我總是忘記。

[^3]: 然而我依然跟vim的hotkey不熟。

[^4]: gitlab、codeberg應該也都可以，如果你想架自己的forgejo，大概也行，總之是個學了不會讓你腳麻帶不走的工具。
