「萬物皆物件」這句話，大概可以排在我最厭惡的十大敘述之一——我的憤怒總是源於不理解，這句話困擾了我非常久的一段時間。

~~我就不知道看到Ruby以「萬物皆物件」掛帥還跑去玩Ruby算不算是一種被虐狂。~~

前幾天我在各種搜索時，又再度被提醒了「In Python, everything is an object」的客觀現實。而就在剛剛，發現[今日額度](https://leetcode.com/problems/copy-list-with-random-pointer/description/)又因為多指一的linked list導致Rust再次被[禁賽]({{< relref "261109_take_care">}})。

![](https://www.blindfiveyearold.com/wp-content/uploads/2015/06/unacceptable-lemongrab-e1434739410519.png)

頓時我陷入某種愁雲慘霧——我後來稍微研究了一下，各個語言應該都有相應的機制能應對，主因是我一直沒能好好把這塊搞清楚；但當下我整個陷入某種熟悉的工具不能使用的焦慮——C當然沒有問題，只是想到要一直`malloc()`就覺得很不舒服。

`malloc()`、`new`其實本質差不了多少——想到這裡我也很想吐嘈自己，如果想要達成多鄰國的境界，實在不該卡在這種地方。

於是我果斷選了C++，霹靂啪啦一陣亂打，然後：

![](blogpics/261111_ac.webp)

終於有點Rust是負重運動的實感了——不是，C++寫起來也太爽了吧[^1]？

然後我比較在意的是這個：

```cpp
auto dummy = new Node(0);
Node* p_d = dummy;
```

跟這個：

```cpp
auto dummy = Node(0);
Node* p_d = &dummy;
```

這讓我突然想到，C++可是一門物件導向的語言。

當下，一連串想法像雷一樣突然打到腦裡。什麼輪胎有滾動的功能，動物會叫，狗會汪汪叫，貓會喵喵叫，物件是把行為跟資料封裝在一起的概念——怎麼封裝？`struct`跟`void*`啊。當初可能只是為了寫起來舒服而發展出來的想法，結果太舒服了，直接成為了一整個世代的核心思想。

C++選擇[誠實]({{< relref "261025_i_aint_the_shit">}})，所以它既提供方便實踐OOP的各種設計，也保留了C的細節；Python、Ruby一類的選擇提供一套統一的操作模式，貫徹「萬物皆物件」的精神來方便使用者，才會有這類[小細節]({{<relrelf "261027_cant_just_go_ghost_on_me">}})需要注意。

道理我都懂，但我怎麼會現在才懂？

後來我在想，該不會是因為，我對C++這類我全都要型的語言的各種躲閃飄，讓我一直沒能把物件跟非物件放在一起看——到底當初在閃什麼啊到底…。

回頭再看，「萬物皆物件」，還真精闢，笑死。

回頭看這個OJ——就像我當初看它只是個打發時間的頭腦體操，我一度想拿著Rust衝破自己對C++的那些積怨，如今它於我，似乎又再次變回那個頭腦體操。我依舊認為Rust是對C++的再整理，如果可以的話我還是想以Rust為主力，不過工具畢竟是工具，它的威力終究是生態系決定的，就像RoR之於Ruby、AI/ML之於Python、web之於go。

也許我該認真考慮摸摸各種相關領域的東西。

[^1]: 儼然是還沒被segfault毒打到剩半口氣的naive發言。
