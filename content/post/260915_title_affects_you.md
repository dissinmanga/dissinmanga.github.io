title: 標題與體裁的暗示/他人對作者的信任度
date: 2026-09-15T07:02:00+00:00
---

當你看到「咒術迴戰」，你會想到什麼畫面？

就算你完全沒有接觸過本作，你也很容易想像到，這是一部用「咒術」不斷「戰鬥」，作者的概念上可能偏重於輪「迴」的作品——我不是說咒術迴戰一定是這樣的漫畫，但，通過提取那些在大眾認知中有重量的詞語，能夠在無形之中跟讀者建立一個默契。

鬼滅之刃也是一例，你一看名字就會知道這是一部用刀子滅殺鬼的故事。

另一個公式是，「葬送的芙莉蓮」——先說我日文能力零，我對本作的理解完全是跟風人的程度——這也很容易讓人聯想到是一部圍繞著芙莉蓮這個主人公，以及回望往事的故事。類似的例子有不少︰食戟之靈（原文為食戟のソーマ）就是一部圍繞著主人公創真不斷與他人進行食戟的故事——再強調，我的日文能力零，食戟的日文可能有它的符號重量。火影忍者（原文為ナルト）即一部圍繞在主人公鳴人的故事；雖然作者中期完全控制不住故事往サスケ的方向跑，只能說繁中代理很有遠見地翻成火影忍者。

幹，我怎麼盡想一些搞死自己的例子。

鏈鋸人，是這個類型的一個異例，看名字你會覺得它是一部關於會變身成鏈鋸的人，從鏈鋸這個形象，也許會想像到這是一個有些血腥、有些粗糙的故事。它完全以主人公的模式推進故事，不取名為鏈鋸人淀治，除了不夠簡潔外，這是一部大家不在意淀治，只在意鏈鋸人的故事。

有些作者甚至會在標題上創造懸念，比如把兩個衝突性強的符號並列，讓人不禁思考起葫蘆裡會賣什麼膏藥。像是，如果把「暗殺」這個肅殺性滿點的符號，跟「教室」這個溫柔成長的符號擺在一起會跑出什麼呢？把「不死」這個人人稱羨的概念，跟「不運」這個大家敬而遠之的概念擺在一起呢？

以精煉性來說，我其實比較喜歡不死不運，但論直覺，肌肉魔法使馬修應該是近年做得很不錯的一部，你一看名字就知道它是圍繞在馬修開展的故事，同時又看得出這恐怕將是一部以肌肉挑戰魔法世界的故事，既有了世界觀（魔法世界）、有了主人公（馬修）、又有了衝突性（肌肉魔法）。

而標題只是提供一個起頭，事實上，從標題開始進到內文，一路上，不論作者有意無意，讀者都是在作者拋出的符號上不斷摸索，你能從內文的經營看出一個作者貼不貼心。

以鬼滅之刃為例，這部的開局混了兩件事，一是作者試圖建立起一個嚴肅的vibe（從滅門事件到不要將自己的生殺大權交給別人等血淋淋的價值觀），另一是作者在替後面滅鬼的場面做設定打底，他一邊透過炭治郎的鍛鍊一邊補上鬼的特質，鬼被斷頭不會死、鬼會再生、鬼會吃人等。咒術呢？序盤上芥見保留了相當多無意義的碎嘴把氣氛拉得很casual，甚至有點漫不經心，但芥見一樣在交代咒術是什麼——由芥見的切入點，你會發現他對基礎設定的建構，在通常的少漫上簡直是隨便到一個地步，他重視的是咒術的源頭——人的負面情緒，這才是所有咒術戰的基礎，他想集中在人們相互詛咒的場景上。

不過，因為這些作者在Jump上連載（事實上我覺得二次元的故事很難走出這個限制），他們其實還有個隱形的限制——必須要是以幻想戰鬥的題材描寫人與人之間的衝突。與此同時，他們省下了做人設給讀者做心理建設的功夫，所以我們很難看到這一面。

這在什麼都可以寫，什麼都不奇怪的blog圈子就會比較常見一些。

以我為例，我當初是想著要把漫畫連同對這個圈子的現狀一起噴的心態建立這個Blog的，並沒有打算以我為核心經營這個blog，所以我沒有給自己這方面的角色取名字，只用「漫畫」告訴你這裡的語境、「嘴」告訴你這邊的文字基調會相對辛辣、「今天」告訴你我對這邊的文字非常不加以修飾，今天想到就開出來噴一篇。

[廢文小天地](https://trashpoosts.com)也是這個風格的取名——我typo放在比較明顯的地方，幫我手動把多出來的那個字母砍掉，這樣他就不會發現我——你一看就知道這是一個廢文為主的小地帶，而廢文這兩個字，本身又隱含了個人性。

最常見的例子是「[Wiwi.Blog｜官大為的部落格](https://wewill.blog)」——老樣子，網域名手動改一下，我不想被他發現我在議論他。挪用了部落格這種舒適寫文的語境，以及圍繞在「官大為」這個人的暗示構成的，非常正確的標題；但相應地，這類blog就非常需要about me做第二波的溝通。

而[Daily Patch Note](https://dailypatchnote.com)，顧名思義可能是個每日會發佈更新內容的網站，切入點頗有自我成長的那個味道，只是patch note一般容易讓人想到軟體，如果在主體上面能提供更多暗示會更好一些。

為什麼我唯獨不對這個網站打碼處理？因為他在七月底就沒有動作了，沒有Daily也沒有New patch，有點可惜。

◆

若要我說經營一個公開發表的空間最直接的作用，那就是作者操作讀者對自己的信任，包括作者付出自己的心意堆疊讀者的信任，或是作者做業配將讀者的信任變現等。不管各種媒體最後會被如何形塑，它一旦出現在公開的地方，就會無形中影響到接觸到的人。在ptt或threads這種容易滋養去脈絡言論的空間待久了，思考會被同化。

我以前最有印象的是在跟故人講了些什麼時，被說我在反串，後來我才慢慢知道「反串」這個詞似乎是從ptt跟一些臉書專頁出來的，作用在讓人對一段論述，先產生「你是在表演」而非「你有話要說」的反應，即降低一個人對外界的預設信任值。

這種討論模式就我所知，最早是從tumblr上開始出現的。

噢不，我好像在做一些會降低信任值的反應，我們回到一些比較有實體的東西上，我們以[【自架站系列】＃1 - 我為什麼（以及如何）決定自己架站？](https://dailypatchnote.com/posts/%E8%87%AA%E6%9E%B6%E7%AB%99%E7%B3%BB%E5%88%971---%E6%88%91%E7%82%BA%E4%BB%80%E9%BA%BC%E4%BB%A5%E5%8F%8A%E5%A6%82%E4%BD%95%E6%B1%BA%E5%AE%9A%E8%87%AA%E5%B7%B1%E6%9E%B6%E7%AB%99/)這篇為例。

這個標題傳遞了一篇即將講述「why and how I decided to self-hosted」的「系列文」，如果看過內文的話，會知道這有個小語病，它其實寫的是「我為什麼決定自己架站，以及我如何架站」，但無妨。比較大的問題在作者made a promise，但過了快兩個月，系列文依然只有一篇，這無形中就會降低信任。

該文作者用了AI產生流程圖，這也是影響信任的因素，不過若沒有相應prompt也生不出對應的圖，所以這方面的影響會傾向於，這篇文的內容可能也有AI參與的痕跡——純手寫的人應該都有感覺，不管寫得再怎麼粗糙，揣著如何虛偽的情感，你當下的虛偽也會是真的，這跟AI那種以某些目的被訓練出來的正確文字是有差別的。如果是在一個追求傳遞正確的場域上，這問題可能會小一些，只要敘述能被檢驗就無妨；但如果是在一個追求溫度與真誠的場域，看的就會是人類參與剪裁的技術，在這層意義上，AI參與的長文章就會滿影響到信任的。

接下來我會採用分段鞭的模式，我是說，分段分析的模式去檢視這篇文章︰

+ 為什麼我決定自己架站？
  + 技術限制——AI協作令技術障礙消失
  + 成本限制
+ 預算規劃與平台選擇（年度總開銷控制在新台幣一千元以下）
  + 網域購買︰市場上一個.com域名的年費通常落在台幣300～500之間
  + 網站主機租用︰免費Hugo靜態網站產生器、和Cloudflare Pages的免費託管
    + Hugo 能夠將Markdown格式的內容、快速轉換為輕量的靜態HTML檔案，讓這些檔案可以直接部署，還不需要有後端伺服器
    + Cloudflare Pages提供了免費的CDN（內容傳遞網路）服務，不僅能加速網站訪問速度，還能提供免費的 SSL 憑證，大幅提升網站的安全性與專業度。
  + 其他功能
    + 留言系統︰Waline、Vercel、Neon
    + 圖片儲存︰Cloudflare Images的免費額度

該作者一開始就表明過他是以AI協作降低實作障礙的模式執行——容我把障礙消失改成降低障礙。說起來把SSG跟伺服器托管混在一起好像有點問題，但這種說法很流行是真的。

+ Hugo客製化與視覺風格打造
    + Hugo提供了許多現成的網站主題，但選擇從零開始搭建，連CSS都自己設定，在排版上我能夠自由調整字體、間距，隨時新增或刪除選單或設計
    + 網站的主體風格定調為「Sketch + Organic」，並給予 AI 我指定的色碼，融合了手繪感線條與不規則造型
    + 同時網站中的部分區塊元素，也採用了不規則的造型，搭配手繪的虛線條，希望能呈現輕鬆、手作感的空間
    + 選用了米杏色與深松綠作為網站的主色調

這邊我就開始覺得有點猛了，Hugo的主題雖然美其名是主題，實際上它牽涉到的東西不少，每個主題是連列表、個人頁、內頁，甚至是內頁需要渲染什麼特殊元件都是主題決定的。就算你是從Hugo官方收錄的主題選來用（噢對，這也是集社群之力打造的，不是Hugo官方「提供」的），你還是可以自己設定CSS，你甚至可以只靠hugo的設定檔改動選單，不用覆寫主題模板也做得到。

這篇文一直讓我感覺到作者踩在一個踩坑記錄與推薦文的語境之間，若是純踩坑的話，很容易在記錄搭建過程中讀到作者的血淚，比如說某些主題的模板寫得比較好改，或是Hugo官方提供的預設模板哪裡有坑。

以「提供了免費的CDN（內容傳遞網路）服務，不僅能加速網站訪問速度，還能提供免費的 SSL 憑證，大幅提升網站的安全性與專業度」這句來說，純踩坑的話，可能頂多寫到解決了CDN跟SSL憑證的痛點，後面那句就會讓我有點遲疑。

我知道原作者可能沒有想這麼多，但這種寫法就會讓我想問，所以你現在是想幹嘛？

不是說推薦文不能寫這些東西，而是，如果要推薦一個東西，Hugo + Cloudflare Page確實是一套解決方案，開發者不用處理後端與伺服器的問題，很省事。點到這個程度就很有效果了。

我會開始想這位作者的現職是不是有這種需要替他人粉飾現狀的工作內容，把沒有很厲害的事說得好像很厲害，但因為底子不夠所以破綻百出。不過只要在秉持著懂多少說多少的方針之下，基本上還不會到懷疑這個作者文章的可信度有多少的程度。

額外一提，如果真的想玩Hugo，除非你對go template跟HTML語法有點概念，不然乖乖用現成主題去改CSS跟templates，先求能動，有餘力再去試著自己寫go，信我。

+ Obsidian or VS Code

我第一次看時差點吐血的段落。

| 特性              | Obsidian                 | VS Code + Front Matter      |
| --------------- | ------------------------ | --------------------------- |
| **主要用途**        | 知識管理、雙向連結、個人筆記           | 程式碼編輯、網站內容管理、寫作             |
| **隱私分離**        | 需手動管理或多個 Vault，易混淆       | 獨立資料夾管理，公開與私人內容易分離          |
| **Hugo 整合**     | 需額外腳本或手動調整               | Front Matter 擴充套件提供良好整合     |
| **Frontmatter** | 需手動撰寫或使用模板，欄位名需自訂        | 可自訂模板與欄位映射，自動生成             |
| **學習曲線**        | 知識圖譜與連結功能較為複雜            | 程式碼編輯器功能強大，Front Matter 易上手 |
| **版本控制**        | 整個 Vault 易被 Git 追蹤，需謹慎配置 | 針對單篇文章資料夾進行 Git 追蹤，更精準      |

Obsidian跟vscode都是資料夾為基礎的editor（vscode的workspace有更彈性的組合法，在此不提），git也是以資料夾為基礎的版控工具。既然知道三者在這方面的設計邏輯相同，主要用途、隱私分離跟版本控制這三欄就可以當沒看到了。

這裡還有另一個坑，Front Matter CMS是專門做給各種blog框架（我不確定是否只限SSG）的GUI管理工具，這名字取得非常的差，如果你知道Front Matter其實是markdown記錄屬性資料的區塊，就會知道這個混淆性不是單把Front Matter寫成Frontmatter就能處理的。

由於我沒用過Front Matter CMS（下稱FM CMS），所以Hugo整合這塊我無從置喙，但Obsidian Templates跟Hugo的模板設定配合好後，理論上是不需要自己填欄位名的。這部份姑且是Obsidian跟FM CMS的設計哲學有出入，Obsidian的Templates語法需要自己研究，且高機率與Hugo Archetype的語法不相容。

所以你要說學習曲線的問題嘛…Obsidian作為一個通用型的筆記軟體，確實無法跟專門做給CMS的工具相比，但這個陡峭的地方絕對是在設定Obsidian與Hugo的相容上，而不是根本不用設定的知識圖譜以及wikilink語法天生與Hugo不相容的連結功能上。

又是一個讓我想很久的地方，這真的是張飛打岳飛的經典例子，Obsidian在這個場合強的地方在於，它可以透過Obsidian Git這個plugin，讓你在手機上也可以把Obsidian當成陽春版的CMS用，搭配Obsidian之前加入的base功能，你要篩出草稿也是a piece of cake——一樣也是稍微需要門檻的。

比較，其實是還滿需要小心處理的議題，先不提欄位的設定，光是事先定義好比較的場域，為什麼要把這些工具拖進這個領域，都是要先處理過的，沒處理好就是純粹的ragebait——噢，我提過他是以新手自居的嗎？

其實第一次看的時候，我壓根沒有查證Front Matter這個詞的模糊性就開噴，之後我來回想了一想，我當時直接不給這篇文機會的主因好像就是在一連串微小的信任磨損之下造成的悲劇，尤其是這個做得最沒廢話的表格，居然還是全文瑕疵最多的地方。

最後一段AI協作就是純然的廢話，略過。

◆

我在想，這也是blog有趣的地方。

我挑的這篇文，就是一篇作者對自己的角色沒有很清楚的例子，一連串看下來，它混雜了作者從無到有生出一個blog的興奮、作者在技術選型上的分享、作者試著給自己選擇一個客觀理由的嘗試，如果停在分享技術選型表示It just works，其實是沒有問題的。

說起來，若以材料的整理來說，大綱或思維導圖的格式其實就已經很足夠，如我前面示範，我刪掉了超級多冗餘的詞。寫成文章一個很大的差別在於給讀者提供一個flow，不過通常大家在寫作時不會那麼在乎這點，單純順著自己的flow寫下去（所以我才會說純手寫的話，連你的虛偽也會是一種真誠）。

而這個信任度就是有趣的地方，沒有人真的知道怎麼寫能夠誘導讀者怎麼想，因為大家的成長背景都不同，只是從吸收媒介與相互感染——我是指互動——的過程會交織出群眾潛意識，很多時候作家其實是在跟這個潛意識搏鬥。所以才會有這種，雖然沒有一個標準答案，但我感覺得出你有想把它記錄下來的企圖，而且選了一個很正式的格式——如果你有發現表格在文章裡很罕見的話——把一個跟架站關聯性相當低的東西整理出來，你想幹嘛？

再寫下去就覺得自己會給人很大的壓力，我平常寫作也不會想這麼多，用力去扮演某種人設，扮久了也習慣的。只是我想，扮演某個人設，滿足背後的預期才是難度的來源。

總之，加油吧。
